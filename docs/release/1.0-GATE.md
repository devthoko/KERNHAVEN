# Status of the 1.0 release gate

Date: 2026-10-29 (M19). Source of the boxes: [Quality gates](QUALITY-GATES.md).

**Result: Kernhaven 1.0 is not complete and must not be tagged.** The
software for all eighteen capabilities is implemented and tested in CI, but
several gate items need the owner (reviews and merges, the release key,
risk acceptances) or infrastructure that does not exist yet (Debian 13
VMs), and some evidence takes time (seven days of nightly fuzzing on
`main`).

Branches (stacked, none merged): `m7-compose` (PR, M2–M7) → `m8-apps` →
`m9-storage` → `m10-files` → `m11-mfa` → `m12-network` → `m13-tls` →
`m14-monitoring` → `m15-alerts` → `m16-backup` → `m17-security` →
`m6b-streaming` → `m18-installer` → `m19-release`.

## What the owner needs to do

1. Review and merge the stacked branches in order.
2. Provide Debian 13 VMs (amd64, arm64) for the integration, upgrade,
   backup/restore and power-loss runs (B-2).
3. Hold the release key ceremony (minisign, offline) and add the public key
   to `deploy/release-keys/` (B-3).
4. Decide the proposed risk acceptances (TH-06, TH-14, TH-41, TH-52) and
   TH-21.
5. Commission or perform the requirement-level ASVS review.
6. Let the nightly fuzzing run seven days on `main`.
